# Build + axiom excerpt

Two excerpts, both from real runs of this tree. The first is the clean build
recorded at packaging time; the second was captured when this documentation was
repaired. Sources are identical in both — no `.lean` file changed.

## 1. Clean build (packaging time)

Commands, run in the repository root:

```bash
lake update
lake clean            # removes project + dependency build artifacts (full clean)
lake build Submission # rebuilds mathlib + PNTAnd + vendored Robin1984 + PGL + BV + Submission
```

Final lines of that build log (5,681 lines; the full log is not committed):


## 2. Re-verification (forced recompile, warm `.lake`)

`.lake` was warm (mathlib, `PrimeNumberTheoremAnd` and the vendored trees already
built from these same committed sources). The three top-level `.lean` sources
were force-recompiled by deleting their build artifacts first, so `Built ...` in
the output is a real compile, not a replay:

```bash
rm .lake/build/lib/lean/PrimeGaps/Bounded246.{olean,ilean,trace}
rm .lake/build/lib/lean/Solution.{olean,ilean,trace}
rm .lake/build/lib/lean/Submission.{olean,ilean,trace}
lake build Submission
```

(Those three lines are shown together; they came from three consecutive

Axiom audit:

```bash

'BigOSpeedrun.PrimeGaps.prime_gap_le_246' depends on axioms: [propext, Classical.choice, Quot.sound]

```

Same three lines, byte for byte, as `axiom-audit.txt` — no other output.

Job totals differ between the two runs (5437 vs 5430) because Lake counts the
actions it walks; a warm tree walks a slightly shorter graph for the same
sources. The load-bearing evidence is the exit status, the
`Build completed successfully` line, and the three axiom lines.
